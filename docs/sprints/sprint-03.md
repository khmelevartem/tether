## Цель спринта

Поднять инструментарий ревью, точечно закрыть два HTTP/discovery-бага, накопившихся к концу спринта 2. К концу спринта:

- скилл code review через специализированных суб-агентов работает и применяется к новым PR — амортизирует затраты на ревью всех будущих задач;
- `FileClient` корректно выставляет `Content-Length` при известном размере файла;
- discovery перестаёт терять пиров на сетях с дубликатами имён сервисов.

## Полезный инкремент

После спринта:

1. **Code-review скилл амортизирует все будущие PR** (#104) — специализированные суб-агенты дают консистентное качество ревью независимо от размера PR. Окупается уже на 3–4 крупных PR.
2. **HTTP-протокол передачи корректен** (#93) — `Content-Length` выставляется → совместимость с `curl` и стандартными HTTP-клиентами для отладки и интеропа.
3. **Discovery надёжнее** (#90) — пиры не теряются на сетях с дубликатами имён сервисов; меньше «исчезающих» устройств в `[peers]`.
