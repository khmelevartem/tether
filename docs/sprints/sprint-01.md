
## Цель спринта

Разблокировать MVP-критический путь. К концу спринта:

- фундамент DI положен (`AppGraph` + правки docs/engineering/dependency-injection.md);
- зафиксировано архитектурное решение по презентационному слою и навигации;
- два discovery-бага закрыты (Android receive в реальной эксплуатации становится надёжным);
- фундамент паринга есть на всех платформах;
- CLI умеет отправлять файлы — это разблокирует ручную отладку и снимает риск с #10.

После этого спринта Android UI и pairing CLI flow можно начинать без архитектурных сюрпризов.

## Полезный инкремент

После спринта:

1. Ставить файл из CLI на Android можно стабильно по времени (#47) и без фантомных дублей пиров (#44).
2. Pairing-фундамент работает на всех платформах (#9) — следующий шаг (#10) встанет на готовый каркас.
3. Зафиксировано решение про UI-стек (#51) — Android UI пишется без архитектурных сюрпризов.
4. DI-граф (#50) даёт единственное место сборки компонентов — все следующие задачи интегрируются туда.
5. CLI с командой `send` (#52) — отлаживать common-логику и Android-receive можно в одну команду в терминале.
